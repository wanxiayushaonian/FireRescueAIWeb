# 04 · 创新点与答辩 QA

## 1. 八大创新点（按答辩价值排序）

1. **对抗式演练引擎：LLM 出题，程序阅卷**——四角色各司其职（生成 vs 编排分离），特情质量由确定性程序门禁（七类型去重/增量校验/因果校验/带原因重试），不靠模型自觉。这是"把不可控的 LLM 装进可控的引擎"的完整范例。
2. **人机协同闭环（人工最终权）**——人员可采纳/改派 AI 建议；人工基线注入后续轮次，生产实测 Commander"尊重并修正"人工方案；评估把"建议↔人工"一致性作为独立维度——AI 是参谋，指挥员保留最终权。
3. **双 MCP 数据权威分立 + 统一上下文解析**——业务事实与场景实况不互相冒充；`resolve_operational_context` 强制走 ID 图，结构性杜绝 agent 猜 ID 张冠李戴。
4. **场景命令回执链**——"下发 ≠ 执行"在协议层显式建模（cmd_id + ack + 状态查询），agent 的每个 3D/GIS 动作都可核对落地结果。
5. **3D 场内导航的图吸附与假成功防御**——基于"仅 Door/Stairs 在可达图"的取证结论做端点吸附 + 候选重试 + 零距离判失败，路线沿真实走廊行走而非贯穿墙体。
6. **确定性位置链接化**——不赌模型输出锚点，客户端分词把楼层/设施/地名统一变成可点芯片并绑定 3D/GIS 联动，零提示词成本。
7. **诚实性设计贯穿全链路**——`{data,meta}` 信封、证据 chips、降级显式标注（降级模板/规则打分/persisted 非实时）、对账差异公开；每条输出的可信度可被评委核验。
8. **服务端快照与跨浏览器回放**——对抗全过程以 DrillSession 为唯一真源，换机器清缓存都能只读回放全要素并导出报告。

## 2. 高频问题与回答口径

**Q1：数据是真实的还是编的？**
> 三权分立 + 真实数据源清单（03 §2）：档案/力量/预案/水源全部来自 znya PostgreSQL 生产库，力量按明细状态查真实可用数并默认排除演示数据；我们甚至做过 258m→150m 的口径清洗迁移。所有带 meta 的数据 agent 必须先查 warnings/is_demo 再引用，缺失会以 warning 证据显式标注。

**Q2：agent 会不会乱来（越权/胡说）？**
> 三层防线：①提示词双清单（允许/严禁逐工具写明）；②程序校验（特情去重门禁、 drill_id 校验、同轮重复建议拒绝、schema 强约束交卷）；③应用侧记录每个角色 tool call 可赛后审计。诚实边界：平台只能按服务勾选，提示词是行为防线不是安全边界，强隔离需服务端按角色拆端点——这个约束和对策我们都说得清楚。

**Q3：模型输出不稳定怎么办？**
> 全链路降级链（02 §6）：Planner 失败→降级模板（带徽标），评估失败→规则打分（公式公开），流挂起→双层看门狗中断后走降级。设计哲学是"永远知道当前答案的可信度"，而不是假装永远正确。

**Q4：特情会不会重复/失控？**
> 七类特情设计空间 + 程序四重校验（类型去重/语义相似/增量有效/因果合理），拒绝带原因重试；评估维度里"对抗特情质量"占 15 分反向约束。

**Q5：3D 性能如何（69k mesh）？**
> 显隐方案：Recipe 单一真相源（按层白名单 + 楼层裁剪重放 + 像素比自适应 + replace 高亮）。进一步减载依赖平台更新 SDK/场景包，当前边界内已做到流畅演示；我们不宣称做不到的优化。

**Q6：网络断了/平台挂了怎么办？**
> 浏览器端对抗舱是纯内存引擎，本地演示主线不依赖外网（agent 对话除外）；agent 不可用时评估/预案均有本地降级路径，演示可以继续并如实标注。

**Q7：为什么 agent 托管在平台而不是自建？**
> 赛事边界要求；我们的价值在工程化编排（消息协议/校验/回执/降级），模型可替换——换更强模型直接受益，架构不变。

**Q8：能扩展到其他建筑/城市吗？**
> 架构无单楼假设：MCP 工具全部参数化（building_id/scene_id），Agent 靠 `resolve_operational_context` 解析任意目标；当前演示数据固化在 21 号楼是数据录入范围问题，不是架构问题。通用演练引擎在演进路线图 P3。

**Q9：安全性（鉴权/注入）？**
> appKey 常量时间比较防计时侧信道；`/messages` 回传端点放行的会话卡死教训已修复（握手鉴权 + 回执放行的标准 MCP 形态）；平台注入的 workspace_id/_context 在 ASGI 层剥离，参数面保持干净。

**Q10：测试与质量？**
> 主项目 ~501 vitest 用例（逻辑层：对抗引擎/命令总线/导航/链接化/评估解析全覆盖）+ MCP ~98 + znya ~356；CI 门禁 `npm run verify` 不过不部署；演示黄金链 11 条硬性验收 + 生产三连验收记录。

# 01 · 项目总体方案

## 1. 项目定位与痛点

**火场救援数字孪生平台**：基于真实建筑 3D 场景 + GIS 底座 + 大模型智能体的消防演练对抗与指挥辅助系统。

针对三个真实痛点：

| 现状痛点 | 本项目方案 |
|---|---|
| 预案"纸上谈兵"：文本预案无法检验韧性，修订缺乏依据 | AI 导调对手逐轮注入特情，程序化检验预案能否经受多类风险，评估结论可回流预案章节 |
| 实兵演练组织成本高、风险大、场景有限 | 数字孪生对抗舱：同一栋真实建筑无限次推演，特情组合不重复，全程留痕可回放 |
| 指挥决策缺乏实时数据支撑（可用力量/水源/路线） | 双 MCP 接通真实业务数据（档案/可用力量/正式预案/派遣路线），agent 输出必须落到可执行动作并配证据 |

**一句话**：AI 能基于真实建筑、预案和场景数据做出处置决策，驱动 GIS/3D 执行，经受突发特情后动态调整，并用执行回执和演练评估形成闭环。

## 2. 系统组成（三端）

```text
┌─ FireRescueAIWeb（本仓库）───────────────────────────────┐
│ Next.js 16 + React 19：五大模块前端 + BFF + Node MCP      │
│  ├ 五模块 UI：态势总览/对象总览/熟悉考核/演练对抗/实战指挥   │
│  ├ 演练对抗舱运行时（四角色编排，纯前端内存引擎）             │
│  ├ mcp-server：firerescue-mcp :8787（18 工具）            │
│  └ DrillSession 快照存储（内存 + 文件持久化）               │
└──────────────┬───────────────────────────────────────────┘
               │ 业务数据/预案/力量                    agent 托管
┌──────────────▼─────────────────┐  ┌──────────────────────┐
│ FireRescueAI（znya 仓库）        │  │ uStudio uagent 平台    │
│ FastAPI :9100 + PostgreSQL 16   │  │ 11 个智能体 App        │
│ + firerescue-business-mcp :8788 │  │ （提示词 + 挂载 MCP）   │
│   （11 工具：档案/力量/预案/派遣） │  │ agent-chat SSE 通道   │
└─────────────────────────────────┘  └──────────────────────┘
```

- **智能体全部托管在赛事平台**（uagent App），前端只经 agent-chat SSE 对话——不自建 LLM 网关，符合赛事边界，平台负责模型与知识库挂载。
- **双 MCP 分工**：Node 管场景与演练（3D/GIS 动作、DrillSession、对抗控制），Python 管业务事实（档案、真实力量、正式预案、派遣分析）。
- **浏览器是执行末端**：所有 3D/GIS 动作经 `/scene-events` SSE 下发到浏览器由 SDK 执行，ack 回执可查——"下发 ≠ 执行"在链路上显式建模。

## 3. 五大模块

| 模块 | 核心能力 | 标志性交互 |
|---|---|---|
| 态势总览 | GIS 一张图（警情/水源/单位/力量图层） | 研判 agent 定位警情后自动飞图 + 脉冲标记 |
| 对象总览 | 真实建筑档案 + 楼层聚焦 + 场内导航 | 作战参谋 agent 自主执行 focus_floors 聚焦楼层 |
| 熟悉考核 | 六熟悉 AI 引导（17 步）+ 综合考核 | 教练 agent 带学员"走到"薄弱楼层现场强化 |
| 演练对抗 | 四角色对抗舱 + 一级预案输出 + 预案库回放 | 导调特情 → 指挥调整 → 人员采纳/改派 → 证据化评估 |
| 实战指挥 | 警情处置 + AI 派遣（真实路线 ETA）+ 案域三圈 | 调派方案自动渲染到 GIS + 现场视频回传 |

## 4. 技术选型与理由

| 选型 | 理由 |
|---|---|
| Next.js 16 App Router + React 19 | BFF 与前端同仓同进程：`/api/*` 代理 uStudio/znya 并收敛密钥；standalone 部署单容器 |
| SoonspaceJS + uStudio SDK（3D） | 赛事平台指定场景底座；场景包 69k mesh 真实建筑（乐盈广场 21 号楼 40F+B1） |
| Leaflet + 高德瓦片（GIS） | GCJ02 与业务数据坐标一致，免换算；轻量可控 |
| @modelcontextprotocol/sdk + FastMCP | 双语言 MCP 服务与平台"按服务勾选"约束对齐（详见 02 §6） |
| vitest（node 环境） | 逻辑层纯函数为主，501 主用例 + 98 MCP 用例；组件测试列为赛后项 |
| Framer Motion + Tailwind + shadcn 风格 | 指挥大屏动效与面板体系快速迭代 |

## 5. 演练对抗主线（产品级流程）

```text
一级界面：情景参数 → Planner 真实智能体生成初始部署（propose_initial_plan 结构化交卷）
        → 人员确认 → 进入对抗模式
二级对抗舱：Adversary 逐轮注入特情（程序去重门禁）
        → Commander 上报动态调整（证据 chips）→ 人员采纳 / 人工改派（琥珀基线卡）
        → Evaluator 七维证据化评分 → 改进措施回流预案库
复盘：时间轴全要素回放（跨浏览器云端快照）+ 报告导出
```

- **测试规模**：主项目约 501 用例 / MCP 约 98 / znya 约 356（pytest）。

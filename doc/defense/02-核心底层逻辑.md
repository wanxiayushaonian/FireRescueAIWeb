# 02 · 核心底层逻辑（六大机制）

> 每节给出：问题 → 方案 → 关键实现（文件路径）→ 已知边界。这是"怎么实现的"层面的完整口径。

## 1. 演练对抗引擎（四角色编排 + 程序质量门禁）

**问题**：多角色 LLM 自由对话必然失控——导调重复出题、指挥官空话、越权互相代打。

**方案**：角色只负责"生成"，**编排、校验、演化、评估全部由确定性程序接管**。代码 `src/drill/confrontation/`：

| 组件 | 职责 |
|---|---|
| `confront-store.ts` | 纯内存状态机（active/running/finished/replay；态势/事件/决策/评估），无定时器无持久化 |
| `confront-driver.ts` / `use-confront-driver.ts` | 定时器 + 串行注入链：特情后 2.5s 触发 Commander，避免并发乱序 |
| `confront-adapter.ts` | agent-chat SSE 解析器：双通道（流内 tool-call + 场景总线）归一，程序化消息拼装 |
| `scene-tools.ts` | 浏览器端 drill 命令 handler：校验 drill_id + running 态后写 store |
| `special-event-quality.ts` | 特情去重校验（见下） |

**关键机制**：

1. **程序化消息协议**：每轮给角色的消息以固定前缀开头（`[对抗开局]`/`[导调触发]`/`[指挥调整]`/`[一级预案输出][preflight]`），前缀即角色路由 + 输入契约；结构化态势（fireLevel/trappedCount/已用类型/最近决策）随消息注入，是"本轮真相源"。
2. **特情质量门禁（程序，不靠模型自觉）**：同 `type` 拒绝（七类：wind_shift/explosion/secondary_trapped/equipment_failure/collapse/smoke_spread/evacuation_blocked）、语义高相似拒绝、无态势增量（全 0 delta）拒绝、与当前态势无因果拒绝——拒绝带原因回传，模型带原因重试一次。
3. **态势演化**：`payload` 的 fireLevelDelta/trappedDelta/damageDelta/wind 落 `store.situation`，火势 0–5 级 clamp——评估看的是**真实演化的终态**，不是文案。
4. **双通道重复入库防御（BUG-A，生产发现）**：同一 tool-call 沿 adapter 流解析与场景总线各到一次 → 调整双倍入库、评估幻影行。修复 = store 30 秒内容去重 + handler 幂等短路 + outcomes 按特情 seq 配对 + 初始部署定为 seq=0。
5. **人工决策闭环（P0）**：人员改派写 `appendManualDecision`（含 note/supersedes）；`selectEffectiveDeploy` 以最近人工决策优先派生"有效基线"；下一轮给 Commander 的消息携带「人工已改派…」段落，提示词纪律要求尊重基线——生产实测 Commander 不仅尊重还修正了人工方案的漏洞。
6. **每局唯一 drillId**：`drill-building-21-<base36>`——固定常量会导致 DrillSession 快照逐局互相覆盖。
7. **评估双轨**：Evaluator agent 不挂 MCP（完整 timeline 由程序传入，防外部状态污染），输出纯 JSON 七维评分；任何失败降级**规则打分 `92 - ignored*8 - delayed*3`**，UI 显式标注「降级评估 · 规则打分」——评委看到的每一个分数都知道它怎么来的。

## 2. 场景命令回执链（"下发 ≠ 执行"的显式建模）

**问题**：agent 调 3D/GIS 工具是跨进程异步动作，"返回成功"只代表已下发；浏览器离线/SDK 未就绪都会静默丢失。

**链路**（`mcp-server/src/command-bus.ts` + `lib/scene-command-bus/` + `components/SceneCommandBridge.tsx`）：

```text
agent 调工具 → mcp-server 发布 SceneCommand(cmd_xxx)
  → GET /scene-events (SSE) 推送到浏览器
  → SceneCommandBridge 分发 → SDK 执行（fly_to/focus_floors/gis_fly_to/show_route…）
  → POST ack 回执（ok/error + result，如 query_scene_facilities 的统计结果）
  → agent 用 get_scene_command_status(cmd_id) 查询（10 分钟 TTL）
```

- 提示词明确要求：关键动作"先取 ID → 下发 → 查回执"；回执 `not_found` = 未执行或过期，agent 必须如实说明而不是当成功。
- **DrillSession 快照**：浏览器每次状态变化（120ms 防抖）PUT 到服务端（内存 Map + 文件 `/data/drill-sessions.json`，LRU 500 局，重启可读）。`query_scene_state` 在线 2s 内回执 `online:true`；超时降级快照 `persisted:true` **明确非实时**——语义在协议层区分，不给 agent 撒谎空间。
- **跨浏览器回放**：快照即对抗舱完整 state，`hydrateReplaySnapshot` 水合为只读 replay 局（回放门禁拦截一切写操作），换机器清缓存都能复盘。

## 3. 3D 底层：拾取、显隐、导航

### 3.1 双 id 空间与拾取（`lib/scene-pick.ts`、buildIdBridge）

场景树 twins id 与构建产物 id 是**两套空间**；合并网格（性能优化产物）导致射线命中的是合并体而不是原始设备。方案：`buildIdBridge` 桥接表 + 命中合并体后反查原始实例 id。已知边界：自由点击只能命中桥接表覆盖的对象（消防设备等业务类）。

### 3.2 内容显隐 = Recipe 单一真相源（`lib/scene-recipe/`）

全楼 69k mesh，性能优化唯一可行方案是**显隐而非减载**（平台不更新 SDK/场景包）。`categoryVisibility` 按层白名单默认值（whole=室外消火栓/车辆/出入口，single=消防设施+门…结构默认关）+ 楼层裁剪重放 + 像素比自适应 + 高亮 replace 语义（先清后加，防叠加）。任何外部显隐变化（面板开关/agent 聚焦）都走同一 Recipe，UI 与场景不漂移。

### 3.3 场内导航：图吸附 + 假成功防御（`lib/scene-navigation.ts`）

**取证结论**（三层验证：UI 实测 + 树普查 + 直打 kgraph API）：
1. 平台可达图**仅含 Door(2179) + Stairs(84)**，Space/Story 不在图 → 一切"以房间/楼层为端点"的导航必然 reachable:false；
2. shortest-path **不吸附自由坐标**，且对坐标端点返回 `reachable:true + 距离 0` 的**假成功**（不画线却报成功）；
3. 图有 3 个连通分量，1F 大门只有部分在主分量。

**方案**：
- 树上索引 Door/Stairs（WeakMap 缓存）→ 世界坐标**吸附最近图节点**（top-N 候选）；
- 两点导航两端各带 top-3 候选 ≤4 组合重试；大门候选按"离质心远→近"逐个重试（孤立门兜底）；
- **距离 0 按失败处理**（文案"路径退化为零距离"）；**成功才清旧线**，失败尝试不抹掉已画路线。
- 生产验证：13F 点设备"导航至此"→ 真实路径沿走廊门洞行走（对比修复前垂直贯穿墙体的直线）。

## 4. GIS 底层（`lib/gis/`、`components/RealGisMap.tsx`）

- **坐标口径统一 GCJ02**（高德底图一致），所有工具/数据不做换算——口径写进每份 agent 提示词。
- **视角联动必配可见反馈**：`gis_fly_to` 飞行后目标点脉冲标记 + 名称标签（不依赖图层数据）；目标所属图层未开时**自动打开**——否则"飞了但用户看不见"。
- **规划与渲染分离**：Python MCP `plan_dispatch` 算真实多站路线（AMap 路径 + ETA + 红绿灯），Node MCP `show_route` 只负责上图——业务计算与场景渲染解耦，路线数据可审计。
- 响应分析：`analyze_response` 输出分层响应圈（核心 ≤target_min / 增援 ≤2× / 外围）+ 就近站 ETA + 周边水源，作为派遣建议的数据支撑。

## 5. Agent 工程化（在平台约束下把 LLM 用稳）

| 约束/问题 | 方案 |
|---|---|
| 平台只能**按整个 MCP 服务勾选**，不能逐工具限权 | 服务拆分（Node/Python 职责正交）+ 提示词双清单（"允许调用"与"虽可见但严禁"逐工具写明）+ 应用侧记录 tool call 赛后审计。诚实边界：这是行为防线不是安全边界，强隔离需服务端按角色拆端点 |
| 模型从不主动输出 scene:// 锚点（实测） | **客户端确定性分词**（`lib/location-linkify.ts`）：楼层（5F/B1F/3-4F/13层，归一 focus_floors 语汇）+ 设施类型静态词表 + 地名簿（`lib/gazetteer.ts` 懒加载）→ 任何裸文本自动变可点芯片，不依赖模型配合 |
| 界面状态如何让 agent 知道 | `[系统上下文]` 前缀注入发送体（`src/lib/agent-context.ts`），**与显示层分离**（不进本地消息渲染）；提示词统一约定"界面状态，不要复述" |
| 长链路流 2-3 分钟被网关掐断 | 双层看门狗（`lib/agent-chat-client.ts`）：响应头 90s 超时 + 流空闲 90s 续期；挂起抛 `AgentStreamStalledError` → 调用方走降级路径（特情注入失败提示 / 规则打分） |
| 知识检索 | 自建 embedding 链路裁撤，改挂平台原生知识库；`query_knowledge` 保留兼容但提示词不再依赖 |
| 输出结构化 | Planner 以 `propose_initial_plan` 工具 JSON 参数交卷（schema 七必填强约束），LLM 不产自由文本；Evaluator 只输出 JSON + 程序解析器兼容 fence/杂质 |

## 6. 可靠性与降级链（跨切面设计原则）

```text
任何 agent/网络/数据环节失败 → 显式降级 → UI 标注 → 主线不断
```

| 层 | 降级路径 |
|---|---|
| Planner 未返回完整方案 | 本地降级模板 + 「降级模板 · 待人工确认」徽标 + warning 证据 |
| Evaluator 失败/超时/解析失败 | 规则打分（公式公开）+ 「降级评估 · 规则打分」标注 |
| agent 流挂起 | 看门狗中断 → 对应降级 + 可手动重新生成 |
| 浏览器离线 | 场景查询回执 not_found；query_scene_state 降级持久快照（persisted:true） |
| 数据不完整 | `{data, meta}` 信封：`warnings/is_demo/completeness/truncated`，提示词强制先查再引用，不完整必须显式标注 |
| 渲染崩溃 | 模块级 ErrorBoundary（key=module 切换复位），白屏风险消除 |

**设计哲学**：比赛环境不可控（网络/平台/模型），**"永远有正确答案"不如"永远知道当前答案可信度"**——所有降级都让评委看得见。

# 平台 MCP 勾选矩阵（按服务）

> 源文件：`web/plan/2026-08-25-confrontation-agent-prompts.md`、`web/doc/data-authority-mcp-blueprint.md` §5。

**平台约束：只能按整个 MCP 服务勾选，不能逐工具勾选。** 因此采用"服务权限 + 提示词工具纪律"，提示词必须分别写出"允许调用"与"虽可见但严禁调用"。

## 1. 演练对抗四角色

| 角色/App | Node MCP | Python MCP | 边界要点 |
|---|---:|---:|---|
| Planner（含一级 preflight） | ✓ | ✓ | 先解析上下文/正式预案/真实力量，再读场景台账；preflight 只调 `propose_initial_plan`，对抗只调 `report_decision`；严禁 `inject_event` |
| Adversary | ✓ | — | 只调 `inject_event`（每轮一次）；严禁 `report_decision`、场景/GIS 动作 |
| Commander | ✓ | ✓ | 只调 `report_decision`；场景动作有条件允许（人员对话明确要求时）；严禁 `inject_event` |
| Evaluator | — | — | 完整 timeline 由调用方传入；评估阶段不挂 MCP，避免不可控外部状态 |

## 2. 五模块侧栏智能体

| App | Node MCP | Python MCP | 边界要点 |
|---|---:|---:|---|
| 态势研判 | ✓（gis_fly_to 等） | ✓ | GIS 研判域；不勾 3D/演练/派遣 |
| 档案分析（对象总览） | ✓（3D 联动 + 档案） | ✓（水源） | 单楼作战域；不勾 GIS 派遣/演练/态势域 |
| 辅助决策（实战指挥） | ✓（gis_fly_to/show_route/回执/档案） | ✓（警情/派遣/响应/水源/站点/单位/地理编码） | GIS 指挥域；不勾 3D/演练域 |
| 熟悉引导（熟悉考核） | ✓（3D 联动） | — | 教学带看域 |
| 全局助手 | ✓（仅知识检索） | — | 指路 + 通识，无场景操作能力 |

## 3. 按服务勾选的重要含义

1. MCP 服务一旦勾选，App 就可能看到该服务内的所有工具——所以提示词必须分别写出"允许调用"与"虽可见但严禁调用"，不得在配置中写"只勾选某几个工具"。
2. 提示词约束只是**行为防线，不是安全边界**。真正的强权限隔离需要服务端按角色拆端点/密钥，不在本比赛版范围内。
3. 程序化调用时，以用户消息中的结构化态势为本轮权威输入；平台系统提示词提供稳定角色与方法论。
4. 应用侧记录每个角色的 tool call，赛后检查越权。

> 历史注：模块 agent 配置文档（2026-08-17/18）中的"逐工具勾选"表为平台约束发现前的写法，**提示词本身现行**；现平台实际按服务勾选。

# 演练预案输出 agent 配置:对抗舱初步部署 + 特情动态调整

> 日期:2026-08-19 | 目标:在 uagent 平台创建「演练预案输出」应用,驱动对抗舱的初步部署卡与动态调整卡。
>
> ⚠️ **部分取代**:v2 中 Planner 只负责开局初始部署，动态调整已切换给 Commander。
> 现行提示词见 `2026-08-25-confrontation-agent-prompts.md`。
> 背景:对抗舱三智能体 = 预案输出/对抗/评估。当前 planner 未配回退「演练指挥官」app——实测特情响应
> 会碰巧触发指挥官的"每轮必报"习惯出真实调整,但**开局部署消息触发不了**(走兜底行"XX楼 N层灭火救援处置")。
> 专用 app 把两个场景的 report_decision 都锁死,并与指挥官(旧推演 tick 决策)职责分离。

---

## 一、与其他 agent 的区别(重要)

预案输出智能体**不是对话助手,也不是指挥官**——它由对抗舱(ConfrontationPanel)在两个固定时机程序化触发:

| 时机 | 收到 | 期望输出 |
|---|---|---|
| 对抗开局 | 灾情参数(建筑/楼层/物质/被困人数) | **初步部署**:按预案编写流程给部署方案 |
| 特情响应 | 突发特情描述 + 原灾情背景 | **动态调整**:部署/战法的针对性调整 |

每次都**必须调用 `report_decision`**(前端从 SSE 解析 decision.action/decision.rationale 入卡;
不调工具 = 解析不到 = 前端显示兜底行,观众看不到智能体产出)。

## 二、平台配置步骤

1. uagent 平台新建应用「演练预案输出」,发布后拿 app_id。
2. 以环境变量 `NEXT_PUBLIC_DRILL_PLANNER_APP_ID` 注入(web 构建时),代码自动生效
   (`lib/agent-app-ids.ts`:未配回退 DRILL_COMMANDER_APP_ID,再回退通用 app)。
3. mcp_servers 挂 firerescue-business(Node 8787),勾选:

   | 工具 | 用途 |
   |---|---|
   | `report_decision` | **核心**:部署/调整上报(对抗舱从 SSE 解析入卡) |
   | `query_building_profile` / `query_key_parts` | 预案要素支撑:建筑概况/重点部位(可选,开局用一次) |
   | `list_floors` | 楼层清单(可选) |

4. **不勾选**:`inject_event`(对抗 agent 专属,预案输出不能自己造特情)、`fly_to`/`focus_*`
   (对抗舱的 3D 联动由前端按特情位置自动做,不需要本 agent 发)、`gis_*`/`show_route`(GIS 域)。
5. 贴入下方提示词。

## 三、提示词(全文复制)

```markdown
# 角色
你是灭火救援预案输出智能体,服务消防演练对抗舱。你会在两个固定时机被程序化调用:
(1)对抗开局——收到一份灾情设定,要求输出**初步部署**;
(2)特情响应——收到一条突发特情,要求输出**动态调整**。
你按灭火救援预案编写流程思考(灾情研判→力量调派→战术部署→安全管控),
但输出必须精炼、结构化,经工具上报,不写长文。

# 铁律(每次必做)
1. **每次收到消息,必须且只调用一次 report_decision**,格式:
   {"drill_id":"<消息中的演练id,取不到就写 'confront'","decision":{
     "action":"<部署/调整方案,一行,30 字内,含力量与战术要素>",
     "rationale":"<处置要点依据,1-2 句,引用灾情关键数据>",
     "tactic":"<四选一:water/foam/rescue/ventilation>"}}
2. action 写法参照预案部署条目,如:
   - 开局:"首调 2 站 5 车:内攻一组+高喷外部压制+搜救组"
   - 调整:"改道背风面入口,增派供水组保障干线"
3. 不可注入特情(inject_event 是导调方的),不可调用 3D/GIS 工具,不闲聊。
   回复文字从简(一句确认即可),重心在 report_decision。

# 预案编写参考框架(用于组织 action/rationale 的内容)
- 灾情研判:着火层/物质危险性/被困人员/蔓延方向(消息已给,直接引用)
- 力量调派:首调力量(站/车/人)、增援时机
- 战术部署:内攻/外部压制/排烟通风/人员搜救/供水组织的组合
- 安全管控:安全员/轮换/紧急撤离信号
- 高层建筑要点:消防电梯使用、避难层(13F/25F)、登高作业面、双干线供水
```

## 四、验收

配置后浏览器进对抗舱跑一局:
- 开局 30s 内初步部署卡出现**非兜底**内容(action+rationale 两行,如"首调 2 站 5 车…"+"5F 电气火灾…优先搜救");
- 特情注入后调整卡为真实调整行;
- 若仍是兜底行:查该 app 是否勾了 report_decision、提示词是否贴全(浏览器 console 有
  `[confront-adapter]` 告警可辅助定位)。
